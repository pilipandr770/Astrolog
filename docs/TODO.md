## 11. Автовосстановление пропущенных сообщений при разрыве связи — СДЕЛАНО

Повод: WhatsApp-сессия иногда рвётся (Meta обрывает соединение, или ты
сам переподключаешь номер через QR) — Evolution в это окно НЕ шлёт
вебхук на новые входящие сообщения, хотя потом подтягивает их в свою
историю чата задним числом. Раньше пропущенные сообщения приходилось
находить и подсовывать боту вручную через `/chat/findMessages`.

- [x] `app/services/catchup.py` — при вебхуке `CONNECTION_UPDATE` со
      `state="open"` сканирует все не-групповые чаты через
      `/chat/findChats`, для чатов с непрочитанным входящим — тянет
      историю через `/chat/findMessages` и прогоняет всё новее
      сохранённого чекпоинта (`last_processed_message_ts`/`_id` в
      `conversations`) через обычный `dialog_manager.handle_message()`,
      от старых к новым. НЕ периодический поллинг — только по факту
      (пере)подключения, с cooldown (`CATCHUP_MIN_INTERVAL_SECONDS`)
      на случай нескольких CONNECTION_UPDATE подряд при нестабильной сети.
- [x] `app/routes/webhook.py` — распознаёт `CONNECTION_UPDATE`/
      `connection.update` до обычной обработки сообщений; реальная форма
      пейлоада Evolution НЕ проверена на живом реконнекте (только по
      документации/предположению) — при первом реальном срабатывании
      сверить по логу `"CONNECTION_UPDATE empfangen: state=..."` и при
      необходимости поправить `_CONNECTION_UPDATE_EVENTS`/извлечение state.
- [x] Побочные исправления по пути: `evolution_api.extract_incoming_message()`
      больше не падает на `message: null` (отредактированные/удалённые
      сообщения WhatsApp) и предпочитает `key.remoteJidAlt` вместо
      `remoteJid` (LID-адресованные сообщения теперь резолвятся на
      настоящий номер контакта, не создают "нового" контакта под LID).
      Пер-номерная блокировка (`threading.Lock` на телефон) в
